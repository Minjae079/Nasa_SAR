# SARSCOPE · NISAR Browse Comparison (Vercel-ready)

A mobile-responsive 3D Earth explorer that uses **real NASA/ASF observation metadata and browse PNG URLs** to show two comparable NISAR L2 GCOV acquisition previews side by side. This is a functional **metadata-and-preview browser**, not an SAR numeric change detector.

## What it does

- Globe.GL Earth can be dragged, zoomed, tapped or clicked.
- Clicking a location calls `/api/coverage` (server-side). It queries the ASF SearchAPI for NISAR GCOV scenes intersecting that point, merges results with the included **2026-11-03 IIT catalog** when relevant, and groups matching observations by track, frame, direction, polarization and processing version (CRID).
- Chooses the latest two distinct acquisition dates *within a matching group*, not simply the two latest unrelated satellite products.
- Offers a dropdown for different matching tracks; displays two NASA ASF browse PNG previews side by side with dates, source links, and error handling.
- IIT button works offline from the catalog metadata and lists **32 unique GCOV scenes across 4 matched groups**; the catalog contains **185 distinct ASF products** (many types) deduplicated from the user's uploaded GeoJSON.
- Other worldwide locations require ASF SearchAPI connectivity and actual NISAR coverage. It never invents observations or images.
- Works on desktop and mobile. Detailed street/satellite map view remains available.

## Important science/architecture limits

1. **Not all world's SAR raw data are downloaded**: this would mean an enormous multi-petabyte data warehouse and is not feasible on Vercel. The backend searches the global ASF catalog **on-demand by clicked location** and uses the supplied IIT metadata as a bootstrap/fallback. It filters GCOV for time matching, but other product types remain represented in the bundled catalog.
2. `*_LATLON.png` is a **full-swath browse preview** generated by NASA/ASF. It is **not a georeferenced campus crop**, nor a guarantee of pixel alignment of Before/After. Side-by-side previews are not evidence of actual ground changes. Numeric analysis requires authenticated HDF5/GeoTIFF subsets, co-registration, masks and a validated algorithm.
3. The 2026-11-03 upload is **historical metadata**, not a periodically downloaded complete archive. API queries run when clicked; response is cached briefly by Vercel. A live API failure falls back only where the IIT uploaded catalog covers the point.
4. Preview image availability depends on NASA/ASF server access; **image fetches could not be verified in this environment**. If NASA requires credentials, configure `EARTHDATA_TOKEN` as a server-side secret in Vercel, subject to NASA's current token authorization mechanism. Never place credentials in `app.js`, HTML or GitHub. If images cannot be fetched, the UI displays a clear error.
5. The backend is a Vercel Node.js Function for metadata + PNG fetching, **not** a Python/ML/HDF5 computation server. Raw multi-GB SAR processing belongs in a separate offline batch/worker pipeline.

## Run locally in VS Code

Requirements: **Node.js 22+** and internet access for Globe.GL, map tiles and NASA live requests.

```bash
cd SARSCOPE_NISAR_Compare_Vercel
npm run dev
```

Open **http://localhost:3000**. Press **Explore Illinois Tech** to see the first real metadata-based image comparison. The available source images will load only if NASA's preview endpoint is accessible. **Do not use Live Server or `python -m http.server`** for this version; they would not run `/api/coverage` and `/api/preview`.

`npm test` runs offline unit tests against the actual uploaded IIT catalog and tests the API handlers with mocks.

## Deploy frontend + backend together on Vercel

1. Unzip the project. The repository root must contain `index.html`, `app.js`, `api/`, `lib/`, `package.json`.
2. Push **all** files to a GitHub repository; the original source HDF5 files are not included.
3. At https://vercel.com/new import the GitHub repository.
4. Framework preset **Other**, Root Directory `./`; leave Build Command empty, and for the static output use project root `.` if the UI asks. Vercel recognizes the `api/*.js` serverless functions automatically; don't configure the root directory to `api/`.
5. Deploy. Check `https://<your-project>.vercel.app/api/coverage?lat=41.83531&lng=-87.627` for JSON and `https://<your-project>.vercel.app/` for the website.
6. If image access requires authentication, configure `EARTHDATA_TOKEN` in Vercel Project Settings → Environment Variables. Never commit it. Some NASA login flows may require additional server auth and cannot be solved by the token alone.

## Files

- `index.html`, `styles.css`, `responsive.css`, `compare.css`, `app.js` — static web frontend.
- `api/coverage.js` — local + live ASF scene lookup and matching.
- `api/preview.js` — domain-restricted PNG proxy with 24 MB response limit.
- `lib/sarCatalog.js` — footprint containment and time-pair matching.
- `api/data/iit_catalog.json` — sanitized metadata and browse links from supplied ASF GeoJSON; 185 unique products, 32 GCOV.
- `dev-server.mjs` — simple local HTTP server using the same backend handlers.
- `test/` — offline tests.

## Scientific next steps

To show actual *the same pixels* of the clicked location in each time period, create AOI-cropped, georeferenced GCOV backscatter rasters (from HDF5 via GDAL), align grids, mask invalid data, convert to comparable contrast-stretched PNGs, and serve those via object storage. Perform quantitative change detection and SAR calibration checks **before** reporting surface changes. This is distinct from browsing full-scene preview images.
